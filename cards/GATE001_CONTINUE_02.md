# GATE001 CONT-02 — уборка и исправление ложного поля

Эксперимент завершён, G1–G5 поставлены. Осталось два административных действия и одно исправление отчёта.

P=E:/opencode_harness_portable/projects/omh-baseline-dom-mcp; PY=E:/opencode_harness_portable/.venv/Scripts/python.exe; CWD=P.

## 1. Исправить отчёт
В `artifacts/GATE001_REPORT.json` поле `sandbox_cleaned=true` поставлено **до** фактической уборки. После реального удаления выставить его по факту; если удаление не удалось — `false` с причиной. Отчёт не переписывать целиком: только это поле и, при необходимости, раздел «незакрытое».

## 2. Завершить уборку
`runtime/GATE001/home/` держат заблокированные файлы (`gateway.lock`, `state.db`, `state.db-wal`, `.dispatcher.lock`, `logs/.__agent.lock`, `logs/mcp-stderr.log`). Владелец — sandbox-bound процесс (`gateway run --idle-exit`, spawn ledger pid 3652).

Порядок:
1. Проверить, что процесс принадлежит **именно песочнице** (по `HERMES_HOME`/аргументам), а не живому профилю.
2. Дождаться его естественного выхода по TTL; если не выходит за разумное время — завершить **только этот** процесс.
3. Удалить `runtime/GATE001/home/` целиком.
4. Проверить, что от песочницы не осталось ни файлов, ни процессов: `runtime/GATE001/` содержит только отчёты, логи и MCP-заглушку, но не `home/`.

**Категорически:** не трогать процессы Hermes Desktop, живого профиля и портабл-venv. Если удалить нельзя без риска для них — остановиться и зафиксировать `sandbox_cleaned=false` с точной причиной.

## 3. Отчёт родителю
`ls runtime/GATE001` (не должно быть `home/`), какие процессы завершены (pid + чем подтверждено, что они песочницы), финальное значение `sandbox_cleaned`, sha256 артефакта после правки.

## Границы
Ничего, кроме этих действий. Продукт, тесты, конфиги, живой профиль — read-only. Ориентир 10 вызовов.
