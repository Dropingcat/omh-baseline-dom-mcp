# GATE001 — изолированный прогон гейта базлайна (G1–G5)

Заказчик разрешил эксперимент (NU-AU006-02). Цель — не «доказать, что гейт работает», а **измерить поведение хоста** в пяти режимах и получить числа для решения. Провал эксперимента — тоже результат, если он зафиксирован доказательно.

## Жёсткие правила изоляции
- Работать в отдельном каталоге `runtime/GATE001/home/` (свой `HERMES_HOME`), отдельный `config.yaml`, отдельные `plugins/`, `sessions/`.
- Живой профиль `C:/Users/Arhys/AppData/Local/hermes` — **read-only**: читать конфиг можно (чтобы понять формат), менять нельзя.
- TTL эксперимента: один прогон ≤ 20 минут; после — удалить `runtime/GATE001/home/` целиком.
- Ни одной реальной задачи, ни одного живого канала, ни одного платного вызова не нужно: используется самая дешёвая доступная модель или локальная.

## Что построить
Тестовый плагин `runtime/GATE001/home/plugins/gate_probe/plugin.py`:
- регистрирует `pre_tool_call`;
- возвращает директиву `block` с сообщением вида «сначала получи базлайн» для всех инструментов, кроме чтения маркера;
- пишет журнал `runtime/GATE001/hook_log.jsonl`: время, имя инструмента, решение, длительность;
- имеет режим «сломаться» (raise) для G4 — переключается файлом-флагом, а не правкой кода.

## Прогоны (каждый — отдельный шаг с доказательством)

**G0. Осуществимость.** Запускается ли вообще отдельная сессия с чужим `HERMES_HOME` и загружается ли плагин. Если нет — зафиксировать точную ошибку и остановиться: это уже ответ («хост нельзя изолировать этим способом»).

**G1. Интерактивный агент.** Задача агенту: создать файл `probe.txt` в песочнице. Ожидание: вызов `write_file`/`terminal` заблокирован, файла нет, агент получил ошибку с текстом гейта. Доказательства: `hook_log.jsonl`, отсутствие файла, сырой ответ.

**G2. Субагент.** В той же сессии поручить субагенту создать другой файл. Ожидание: его вызовы тоже проходят через хук (видно в `hook_log.jsonl` с признаком дочернего процесса). Если хук не срабатывает — это ключевой отрицательный результат: гейт на уровне хоста закрывает только главного агента.

**G3. Неинтерактивный режим.** Один прогон без человека (cron/one-shot). Ожидание: не зависает навсегда; либо типизированный отказ, либо завершение с ошибкой за разумное время. Доказательство: длительность и код завершения.

**G4. Отказ хука.** Включить режим «raise». Ожидание: вызов проходит (fail-open). Доказательство: файл создан, в журнале запись об исключении.

**G5. MCP против встроенных.** Один вызов встроенного инструмента и один вызов MCP-инструмента (любой доступный в песочнице). Ожидание: решение гейта применяется к обоим. Если к MCP не применяется — зафиксировать как дыру.

## Замеры
Для каждого прогона: задержка хука (мс, минимум 20 замеров), число блокировок, число ложных блокировок, что видел агент (текст ошибки), что произошло на диске.
