## Препятствия для свежего агента (кроме H1–H5 из первого захода)
| # | Что | Почему мешает |
|---|---|---|
| H6 | `dom_resume`/pending не показывает текст кандидата; `dom_review` принимает только `candidate_id + intent_digest`. Ревьюер подписывает «точный дайджест», **не имея способа прочитать, что он подписывает** | ревью превращается в формальность; в этом пилоте я ревьюил вслепую, потому что знал содержимое как автор. Нужен безопасный просмотр кандидата для роли reviewer в своём гранте |
| H7 | Политика фиксирует требования `R1`, `R2` и ветки `AA`, `AB`. Свои требования/ветки проект завести не может | «развернуть ветки» сейчас невозможно: можно только заполнять заранее заданные. Нужен путь объявить требование и ветку |
| H8 | Создание клайма требует вручную собрать JSON со всеми обязательными полями, base64 тела, `metadata` по типу, `external_task_ref`, `policy_digest`. Ни подсказки схемы в ответе, ни помощника | у меня это заняло скрипт на фикстурах. Агент без чтения кода не соберёт. Нужен шаблон/`dom_describe` с примером на каждый тип |
| H9 | После `STALE_REVIEW` кандидат в `dom_resume` по-прежнему `state=REVIEWED`; нигде не сказано, что основание ушло с AA:2 на AA:3 и что делать | агент повторит admit и получит тот же отказ без объяснения. Нужны: состояние `STALE` с `dependencies_now` и подсказкой «пересоберите на AA:3, нужно новое ревью» (это W2/C4) |
| H10 | Самоприёмка запрещена по `root`, а root определяется ролью запуска. Я один человек за обоих — разделение формальное | в боевом режиме независимость должен давать другой агент/сессия, не другой процесс |
| H11 | `dom_sync` остаётся `pending` (YAML_EXPORT, OMH_EVIDENCE) — доставку нужно запускать отдельно | readiness не станет READY, пока агент не вызовет sync; из resume не очевидно |

## Вывод по вопросу «как будет проводиться внесение задач в клаймы и развёртывание веток»
- **Внесение в клаймы работает**, цикл submit → review → admit проходит, ревизии растут (AA 0→3), происхождение и зависимости сохраняются.
- **Ветвление пока не развёртывается**: набор веток/требований вшит в политику (H7). Это главное, чего не хватает, чтобы вести через DOM реальный проект.
- **Устаревание ловится на допуске (O1), но не объясняется** (H9).
- **Ревью вслепую** (H6) — самое серьёзное для приёмки: сейчас роль reviewer не может проверить то, что подписывает.
