## 1. Принятая модель идентичности и дерева (RS003 DL-03/DL-04, подтверждено AN004)

- `record_id` (существующий `claims.id`) — неизменяемая версия/запись. `family_id` (новый sidecar) — общий логический ID семьи клайма. `parent_record_id` — ссылка на родителя при уточнении. Общий `family_id` НЕ нарушает неизменяемость отдельных записей — прежнее заявление оркестратора об обратном было ошибкой, исправлено AN004/RS004.
- Дерево — производный вид: родитель сверху, новые версии того же логического клайма вложены (смысл подтверждён заказчиком дословно, REQUIREMENTS.md «седьмое уточнение»).
- `current leaf` = `tips(family, branch, revision)`. `|tips|=1` → один актуальный; `|tips|>1` → `FORKED`, без молчаливого победителя.

| Механизм | Scope | Статус |

| **Авто-обнаружение расщепления без декларации intent** | Одна семья | `needs_user`; рекомендация RS004 если да — явная связь `contradicts`, допущенная НЕЗАВИСИМЫМ ревьюером; keyword-похожесть и суждение LLM отклонены как единственный критерий |

## 3. Граф похожести по keywords (NU-01, Q-L2-02/05-Б)

Два РАЗНЫХ открытых вопроса, не один:
- **Место keyword** — на клайме (К1) / на связи (К2) / оба (К3). Ответ заказчика «да» на «или» не выбор — нужен один из К1/К2/К3.
- **Scope похожести** — одно дерево (`family_id`) или кросс-family. Безопасность видимости (не раскрывать скрытую ветку через подсказку) уже решена существующим scope-first правилом (Q-L-09/10); продуктовая граница «одно дерево/много» остаётся открытой, рекомендация по умолчанию — только внутри одного дерева.

Новый риск того же класса, что TD-DOM-19: keyword-similarity-канал может выдать существование клайма в невидимой ветке, если разрешён кросс-family без scope-фильтра.

## 4. Сшивка клайма с пунктом плана OMH (Q-L2-03/06)

Факт подтверждён дважды (AN004 и RS004 независимо, включая живой `tool_describe(omh_todo)` и чтение `todo_store.py`): **у пункта плана OMH НЕТ стабильного ID** — адресация позиционная + префикс текста; `set` заменяет список целиком без истории; единственный дайджест — по всему списку, не по пункту.

Требование к DOM: клайм обязан сохранить при создании ссылки И дословный текст пункта, И его sha256 — не номер. `pin_behind` обязан срабатывать на изменение текста на позиции ИЛИ на исчезновение позиции при `set`, независимо друг от друга (проверено синтетическим прототипом RS004, 3/3).

**Причинная реконструкция (Q-L2-06):** сравнение `server_time` (уже существующее поле каждого события) достаточно и детерминировано, включая явное обнаружение одновременности (не разрешать тихо по порядку вставки). Рекомендован отдельный тип события для разовой фиксации факта, а не перевычисление каждый раз. Проверено (5/5).

## 5. Сходимость — merges ≠ converge (ESC-02, подтверждена AN004/RS004, не ослаблена)

Оркестраторский минимум («пара record_id + код причины») был структурно недостаточен для ОБОИХ механизмов:
- **`merges`** — tips-уровень, n-арная (может быть больше двух конкурирующих версий), relation-событие на конкретную семью.
- **`converge`** — branch-уровень, вектор ревизий + `criteria_digest` + субъект + цепочка `supersedes` (DL-08).

Оба остаются `NOT_IMPLEMENTED`. UD-06/NU-04 (субъект/критерии сходимости) остаются открытыми независимо от формы записи.
