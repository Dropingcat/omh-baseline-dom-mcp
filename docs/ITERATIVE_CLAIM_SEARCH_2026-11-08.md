# Основная функция поиска: итеративный обход клаймов по вопросу агента

Статус: формализация прямого требования заказчика (REQUIREMENTS.md §9); не реализованный API, не новый планировщик и не выполненный E2E. Имена полей ниже — проектные понятия, не названия существующих инструментов. Технические детали требуют проверки/исследования, а не молчаливого внедрения.

## 1. Принятое поведение

Исходный вопрос A → доступный клайм AA11 и граф его окружения → агент выбирает заинтересовавший его клайм B, связанный с A → запрос B и его окружения → следующий подходящий узел → повтор, пока новые узлы перестают давать релевантное исходному вопросу продолжение.

Клайм с происхождением и доступным окружением — уже описанный заказчиком способ передачи контекста/оснований. Не требуется ещё раз спрашивать, выбирает ли он «только ссылку» или «весь пакет AB». Ссылка на исходную ветку не выдаёт доступ ко всей ветке.

Глубина одного окружения (рабочие параметры тестирования: минимум 1, потолок 3) НЕ ограничивает всю цепочку поиска: при выборе нового центра отсчёт локальной глубины начинается заново. Права при этом не меняются.

## 2. Разделение обязанностей

- OMH: задача, исходный вопрос, критерии результата, разрешённая область работы; итоговое решение о закрытии задачи.
- DOM: точные версии клаймов, происхождение, типизированные связи и доступные соседние узлы; авторизация каждого запроса/перехода и воспроизводимое представление чтения.
- Агент: сопоставляет окружение с исходным вопросом, выбирает следующий узел и объясняет выбор; не заменяет исходный вопрос тематикой последнего прочитанного узла.
- Журнал поиска: связывает исходный вопрос, запрошенные версии, полученные ссылки, выборы/причины и остановку. Место хранения/контракт ещё определить; наличие ContextPack/сессионного поиска в продукте не утверждается.

Поиск читает и сопоставляет; сам по себе не создаёт принятую связь, merge или converge и не принимает клайм как истину.

## 3. Предлагаемый минимум контракта одного шага (проект, не окончательная схема)

Вход: ссылка на исходный вопрос/задачу; выбранный record_id или разрешённый начальный запрос; желаемая локальная глубина; привязка к виду чтения/версии. Права берутся из доверенного контекста, не из произвольного поля запроса агента.
Выход: выбранный клайм и его точная версия; происхождение (всегда для доступного клайма, включая явно расшаренный); доступные узлы/рёбра с типом, направлением и версиями; состояние актуальности; данные для следующего запроса. При ограниченной выдаче честно указать неполноту в доступной области, без счётчиков невидимых веток.

Для проектирования расширять существующие RS003 VersionRef/GraphEdgeDTO/ScopedGraphPage/ReadView/CursorToken (runtime/RS003/contracts.schema.json), а не вводить параллельную несовместимую схему. В частности, текущие схемы additionalProperties=false, поэтому новые поля требуют явной версии/изменения контракта. Это исследовательские схемы, не доказательство работающего графового API.

## 4. Предлагаемое состояние маршрута и остановка (инженерная гипотеза)

Держать исходный вопрос неизменным; последующие уточнения вопроса — явные версии. Хранить просмотренные версии, ещё не проверенные доступные кандидаты и путь «откуда узел найден». Не смешивать visited-family и visited-record: новая версия уже известной семьи не обязательно уже прочитана.

Не зацикливаться на A→B→A; не получать одну и ту же неизменённую версию снова без причины. Если выбранный путь разошёлся с вопросом, вернуться к другим уже найденным кандидатам, а не объявлять весь поиск исчерпанным по одному тупику. Эту политику фронтира проверить симуляцией, не считать уже согласованным алгоритмом ранжирования.

Различать причины остановки:
- ответ достаточно обоснован относительно критериев задачи;
- доступные релевантные продолжения исчерпаны;
- остановлен отдельный нерелевантный путь, но остаются другие кандидаты;
- достигнут ресурсный лимит/прерывание — поиск НЕ исчерпан, можно продолжить;
- ошибка, смена прав или устаревание вида чтения — требуется восстановление/перепроверка, не «связей нет».

Метод релевантности, ранжирование кандидатов, численные пороги, размер ответа, общий бюджет и политика обновления снимка остаются техническими вопросами для исследования. Keywords К1/К2/К3 не выбраны; их сравнивать на этом рабочем сценарии. Минимальная глубина не должна отсекать многошаговые ответы только потому, что они дальше трёх рёбер от первого центра.

## 5. Сквозные проверки для последующих карт

SEARCH-USE-01: нужный ответ дальше трёх рёбер от исходного AA11; последовательный выбор новых центров на глубине 1 должен позволить дойти до него без расширения прав.
SEARCH-USE-02: в одном окружении есть отвлекающий и полезный пути; нерелевантный тупик не прекращает проверку остальных доступных кандидатов.
SEARCH-USE-03: циклы A→B→A и ромбы A→B/D→C не вызывают бесконечные повторы одной версии; после прерывания маршрут восстанавливается.
SEARCH-USE-04: общий клайм из AB доступен AA; происхождение видно, соседние закрытые клаймы не открываются автоматически ни при следующем запросе, ни при повышении глубины.
SEARCH-USE-05: между шагами изменена версия клайма/связи или права; не смешиваются молча старый и новый виды чтения, есть честный путь продолжения.
SEARCH-USE-06: большое окружение/пагинация/лимит времени не выдаются за отсутствие релевантных связей; нет утечки через counts/cursor.
SEARCH-USE-07: сравнение К0/К1/К2/К3 на одном корпусе и вопросах: дошёл ли агент до нужных оснований, потерял ли исходную цель, сколько повторов/лишних раскрытий, какие ложные пропуски и утечки. Не выбирать вариант без этого прогона.
SEARCH-USE-08: находка похожего клайма не подменяет независимую проверку истинности/применимости, мердж или сходимость.

## 6. Граница текущего аудита

AU005 получает требование как критерий пригодности долгому проекту. Проверяет существующие пути, явно отмечает отсутствующий граф/поиск как GAP, не реализует новый API и не объявляет сценарии выше пройденными без фактического прогона. Следующая аналитическая/исследовательская карта должна содержать исходные слова из REQUIREMENTS.md §9, эту спецификацию как проектную интерпретацию и результаты AU005.
