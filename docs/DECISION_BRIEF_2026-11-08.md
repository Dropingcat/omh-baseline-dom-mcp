### Трудности, которые я называл в сессии (сообщение 4767, сессия Bot Chat, 03.11) — поднято дословно по смыслу
1. Совпадение смысла — суждение, а не вычисление. Код admission.py — детерминированный Python без LLM; он умеет только байт-точное сравнение (sha256).
2. Автосхлопывание «последние 2–4 уровня похожи → дубль» может скрыть реальное отличие: уточнение №3 похоже на №1, но содержит ту правку, ради которой написано. Число уровней годится как ТРИГГЕР ревью, не как критерий принятия.
3. Сейчас `converge` — один булев флаг на ветку (projections.py:46), без вектора ревизий и без критерия. Слишком грубо (AN004 ESC-02: нужны `merges` ≠ `converge`, `criteria_digest`, `supersedes`).
4. Правдивость обоснования отличий (`distinguishes_from`) код не проверяет; форму принудить можно, правду — только независимый ревьюер. Надёжный сигнал «агент не читал» — расхождение между доставленным context pack (хеш в delivery_attempts) и написанным.
5. Расхождение AA и AB само по себе — свойство изоляции (я спрашивал, нужна ли принудительная сверка; заказчик теперь отвечает: сводит внутренний куратор).

### Что добавляет решение «куратор LLM внутри DOM» — новые трудности (мои, проверяются в тестах)
- Граница доверия. Куратор должен видеть клаймы нескольких веток, чтобы их сводить. Это ровно класс TD19/AU004-F-01: любой его вывод, показанный AA-only, не должен раскрывать существование или содержимое AB. Вывод куратора = кандидат с видимостью union; в AA-only показывается только после фильтра.
- Детерминизм. Предложение куратора — гипотеза (правило проекта: LLM даёт гипотезы, код проверяет). Принятие остаётся за независимым допуском (submit → review → admit); автор (куратор) себя не принимает.
- Инъекции. Тексты клаймов — недоверенные данные для LLM; куратору нельзя давать инструменты записи в обход допуска.
- Стоимость и отказ. Куратор вне транзакции записи: падение/лимит LLM не должно блокировать приём клаймов; работа в очереди, с повтором и записью причины отказа.
- Воспроизводимость. Каждое предложение хранит вход (record_id версий + sha256), модель, промпт-версию, ответ; иначе схождение нельзя проверить задним числом.

### Следствия для плана
1. Исправление AU004-F-01 идёт первым (граф и куратор без него небезопасны).
2. Keywords: тест-план «К1 / К2 / К3» — три симуляции на одном наборе данных, одинаковые сценарии (поиск клайма по теме, поиск связи по смыслу, скрытый keyword из AB, отзыв keyword append-only, исторический поиск), метрики и критерий выбора фиксируются ДО прогона.
3. Граф: depth=1..3 как тестовые параметры; обязательный негативный набор — foreign-ветка на каждом хопе, счётчики, курсор.
4. Куратор/схождение: сначала карта контрактов и негативный набор (аналитик → ресерчер), потом реализация.

## Решение заказчика по O2 — 2026-11-08 (дополнение, без изменения прежних записей)

Для клайма, который читатель уже вправе получить (включая явно расшаренный через applicability), происхождение сохраняется в публичном представлении, даже если ветка происхождения не входит в launch-grant читателя. Предложенная ранее оркестратором опция (б) отклонена заказчиком.

Граница решения: видимость происхождения доступного клайма не даёт доступ к содержимому его исходной ветки и не разрешает раскрывать произвольные чужие dependencies/head revisions/diagnostic locators. ClaimItem.applicability и excluded_branches не приравнивать автоматически к происхождению: раскрытие ими посторонних веток этим решением отдельно не согласовано. O1 (staleness) и O3 (ack YAML) этим ответом не решены. O2 следует разделить на разрешённую provenance-часть и остальные поля; не объявлять весь O2 закрытым.

Учесть это решение в продолжении AU005/RS005: прежний грант-критерий нельзя применять к происхождению доступного клайма как к нарушению; исторические прогоны и вердикты не переписывать. Это изменение требований, не подтверждение исправления или приёмки продукта.

- всё сделанное вне базы **обязано регистрироваться** записью «вне базы» с путём артефакта, sha256, намерением и временем;
- при восстановлении записи **не воспроизводятся как факты**, а перепроверяются по артефактам (наличие, хеш, структура); нерешённое остаётся видимым счётчиком;
- без суждения (недоступен LLM-куратор/трибунал) — только `PROVISIONAL`, никакой автоматической сходимости и классификации влияния.

Процедура: docs/PROCEDURE_DOM_OUTAGE_RECONCILIATION_2026-11-08.md (коды `OUT_OF_BASE_ENTRY`, `RECONCILED_VERIFIED/CHANGED/MISSING/MALFORMED/ALREADY_RECORDED`, `PLAN_OUT_OF_BASE`, `INCIDENT_DOM_OUTAGE`).

Границы: (1) журнал остаётся очередью черновиков, второго источника правды нет; (2) NU-AU006-02 остаётся **открытым** — F-01 не может считаться проверенным без живого прогона гейта; (3) реализация и приёмка — только через worker + независимые reviewer/auditor.
