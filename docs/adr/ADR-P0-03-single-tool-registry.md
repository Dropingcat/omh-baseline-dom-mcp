# ADR-P0-03. Единый реестр инструментов

- Статус: Accepted
- Дата: 2026-11-11
- Ветка: `arch/p0-invariants`
- Долг: TD-DOM-35
- Аудит: `docs/AUDIT_2026-11-11_ARCHITECTURE_ANALYSIS.md` §P0.3

## Контекст

`server.py` держал три независимых списка: `TOOLS` (JSON Schema),
`SIGNATURE` (типы аргументов) и цепочку `if` в `dispatch`. Инструмент мог быть
объявлен, но не маршрутизирован, или наоборот. Теста соответствия не было.

## Решение

Добавлен `HANDLERS` — единственная таблица `name -> handler`. `dispatch`
проверяет видимость профиля, валидирует аргументы через `SIGNATURE`, затем
берёт обработчик из `HANDLERS`; отсутствие обработчика — структурированный
`UNKNOWN_TOOL`, не `None`.

Инварианты зафиксированы тестом:

- `set(HANDLERS) == set(SIGNATURE)`;
- `STRICT_TOOL_NAMES == set(SIGNATURE)` (strict включает lite-инструменты);
- `LITE_TOOL_NAMES <= STRICT_TOOL_NAMES`, каждый видимый lite-инструмент
  имеет подпись;
- множества аргументов JSON Schema совпадают с `SIGNATURE`; для `dom_claim`
  проверяются все ветви `oneOf` с per-type required;
- `dom_start` — единственное документированное исключение: схема требует
  `request`, подпись оставляет его опциональным, чтобы отказ был доменным, а
  не транспортным.

## Последствия

- Новый инструмент требует schema + signature + handler; drift-тест падает,
  если чего-то нет.
- Порядок `if` больше не влияет на маршрутизацию.
- Поведение и тексты отказов не изменились.
